# 관리자 탭 / Firestore 보안 규칙

## 무엇이 추가됐나

- 상단에 **관리자** 탭이 생겼습니다. `jongyouna@gmail.com`으로 로그인했을 때만 보입니다.
- 구글 로그인한 사용자는 로그인할 때마다 Firestore `users/{uid}` 문서에 접속 기록을 남깁니다.
- 관리자 탭에서 할 수 있는 일:
  - 사용자 목록 조회 (이름, 이메일, 가입일, 최근 접속, 접속 횟수, 저장 그래프 수)
  - 검색 · 상태 필터(관리자만 / 차단된 사용자만) · 열 클릭 정렬
  - **관리자 지정 / 권한 회수** — 다른 사람에게도 관리자 탭을 열어줍니다
  - **차단 / 차단 해제** — 차단된 계정은 로그인 직후 자동 로그아웃되고, 저장 그래프에도 접근할 수 없습니다
  - **데이터 삭제** — 그 사용자가 저장한 그래프와 접속 기록을 지웁니다

## 반드시 해야 하는 설정: 보안 규칙 게시

화면에서 관리자 탭 버튼을 숨기는 것은 **접근 제어가 아닙니다.** 실제 차단은 Firestore 보안 규칙이
합니다. 저장소 루트의 `firestore.rules` 내용을 그대로 게시해야 이 기능이 의도대로 동작합니다.

1. [Firebase 콘솔](https://console.firebase.google.com/) → 프로젝트 `buja-map-b52eb`
2. 좌측 메뉴 **Firestore Database** → 상단 **규칙** 탭
3. 편집창의 내용을 지우고 `firestore.rules` 파일 내용을 붙여넣기
4. **게시** 버튼 클릭

게시 전까지는 기본 규칙(대개 전체 거부 또는 전체 허용)이 적용되어, 저장 그래프가 저장되지 않거나
반대로 아무나 남의 데이터를 읽을 수 있는 상태가 됩니다.

## 규칙이 보장하는 것

| 대상 | users 컬렉션 | 본인 저장 그래프 | 남의 저장 그래프 |
|---|---|---|---|
| 비로그인 | 접근 불가 | 접근 불가 | 접근 불가 |
| 일반 사용자 | 본인 문서만 읽기 / 프로필만 수정 | 읽기·쓰기 | 접근 불가 |
| 차단된 사용자 | 본인 문서만 읽기 | **접근 불가** | 접근 불가 |
| 관리자 | 전체 읽기 / role·blocked 수정 / 삭제 | 읽기·쓰기 | 읽기·삭제 |

핵심 방어선은 다음 두 줄입니다.

- 사용자가 **자기 문서를 처음 만들 때** `role`은 `'user'`, `blocked`는 `false`로 고정됩니다.
  스스로 관리자로 승격하거나 차단을 풀 수 없습니다.
- 사용자가 **자기 문서를 수정할 때** `role`과 `blocked`는 기존 값과 같아야 합니다.
  프로필과 접속 기록만 갱신할 수 있습니다.

## 최초 관리자 이메일을 바꾸려면

두 곳을 **같이** 고쳐야 합니다. 한쪽만 고치면 탭은 보이는데 데이터를 못 읽거나, 그 반대가 됩니다.

- `index.html` 의 `ROOT_ADMIN_EMAILS`
- `firestore.rules` 의 `isRootAdmin()` 안의 이메일 주소 (고친 뒤 콘솔에서 다시 게시)

최초 관리자는 안전장치로 관리자 탭에서 권한 회수·차단이 불가능합니다. 본인 계정도 마찬가지입니다.

## 할 수 없는 것

**로그인 계정 자체의 삭제**는 관리자 탭에서 못 합니다. 클라이언트 SDK는 남의 Authentication 계정을
지울 수 없기 때문입니다. 계정을 완전히 없애려면 Firebase 콘솔 → **Authentication → Users**에서
직접 삭제하거나, Admin SDK를 쓰는 서버(예: Cloud Functions)를 따로 두어야 합니다.

관리자 탭의 **차단**은 그 대안입니다. 계정은 남지만 로그인해도 즉시 로그아웃되고 데이터에 접근할 수
없으므로 실질적인 효과는 같습니다.
